# 밤실 공방 · 모바일 런타임 에셋 1.0

제작일: 2026-10-18. 원본 미술 팩은 변경하지 않았습니다. 이 팩은 같은 이미지의 크기와 파일 인코딩을 최적화한 모바일 전달용 파생본입니다.

## 포함 파일

- 기본 전달본: WebP 17개와 원본 그대로인 SVG 75개, 총 92개 논리 자산
- 선택형 PNG 폴백 17개: 같은 크기와 앵커를 가진 대체 파일. `png_fallbacks/`에 분리
- `runtime_manifest.json`: 원본 매핑·해시·크기·앵커·알파 검사·폴백·장면별 용량/메모리 예상치
- 한국어 DOM 라벨, 정규 레벨 데이터, 폰트 라이선스, 벡터 사용 가이드
- `previews/mobile_runtime_comparison.png`: PNG 기준본과 WebP 디코드 결과의 정지 비교

배경은 1152×768, 여울과 꽃은 512×512, 솜새는 384×384입니다. 배경은 WebP quality 82, 투명 스프라이트는 손실 없는 WebP입니다. 축소된 PNG와 RGBA 모든 픽셀 및 알파가 일치하는지 확인했습니다. 축소는 premultiplied-alpha Lanczos로 수행한 후 straight RGBA로 저장했습니다. 잘라내기, 알파 임계값 제거, 색상 수정은 하지 않았습니다.

## 실제 파일 크기와 초기 로드 계획

전체 92개 기본 전달본 합계는 1,916,295바이트(약 1.92MB)입니다. 이 중 WebP 17개는 1,754,360바이트입니다. 선택형 PNG 폴백 17개는 6,979,922바이트이며 기본 전달본과 동시에 받지 않습니다.

아래 계획은 모든 여울 6자세·솜새 3자세와 기본·고대비 UI 30개를 공통 자산으로 보유하는 보수적인 이미지 계획입니다. 온실에서는 원화 꽃 4개를 사용하고, 대체 벡터 꽃 4개는 추가로 로드하지 않습니다.

| 활성 장면 | WebP+SVG 파일 | PNG 폴백+SVG 파일 | RGBA 텍스처 예상 | 결과 도식 1개 추가 |
|---|---:|---:|---:|---:|
| 실빛다리 | 1,021,110 B | 2,526,858 B | 13.82 MiB | 16.32 MiB |
| 반달 온실 | 1,564,633 B | 3,384,578 B | 17.29 MiB | 19.79 MiB |
| 접히는 방 | 989,896 B | 2,475,674 B | 13.94 MiB | 16.44 MiB |
| 구름 우체역 | 1,022,222 B | 2,704,965 B | 13.65 MiB | 16.15 MiB |

설계서의 초기 전송 8,000,000바이트 목표에는 앱 코드, 실제 음원, 폰트와 요청 부가비용도 들어갑니다. 필수 음향 2,000,000바이트를 예약하면 WebP+SVG 이미지와 합쳐 장면별 약 2.99–3.56MB입니다. 이는 전체 앱의 8MB 목표 달성을 증명하지 않습니다. 오디오는 이 팩에 포함하지 않았고 실제 네트워크 전송과 캐시도 측정하지 않았습니다.

ZIP은 모든 장면, 두 포맷, 검수 자료를 담은 개발용 묶음입니다. 초기 다운로드 크기와 다릅니다. 모든 PNG 폴백과 SVG를 한꺼번에 로드하면 7,141,857바이트이므로 오디오 2MB를 더했을 때 목표를 초과합니다. 장면별 선택 로드가 필요합니다.

## 디코드 메모리 예상치의 한계

설계서는 GPU 메모리의 숫자 상한을 지정하지 않았습니다. 표의 메모리는 가로×세로×4바이트와 SVG의 원래 viewBox 크기 1배 래스터화를 합산한 예상치입니다. WebP가 작아져도 디코드 후 메모리는 같은 크기 PNG와 같습니다.

브라우저의 CPU/GPU 이중 복사, 임시 디코드 버퍼, canvas/backbuffer, 오디오, 앱 코드, mipmap, 전환 중 두 장면 동시 보유는 제외했습니다. SVG를 두 배 크기로 래스터화하면 해당 SVG 부분은 네 배가 됩니다. 이 경우 플레이 화면 추정치는 장면별 약 21.41–23.97 MiB로 늘며 결과 도식과 기타 비용은 별도입니다. Mipmap은 텍스처 부분에 대략 4/3배가 추가될 수 있습니다. 이 숫자를 실기기 메모리 측정 결과로 사용하지 마세요.

## 로드와 해제 순서

1. WebP 디코드를 한 번 확인합니다. 불가능하거나 디코드에 실패하면 해당 자산의 `pngFallbackPath`를 사용합니다. 같은 자산의 WebP와 PNG를 동시에 preload하지 않습니다.
2. 공통 UI·캐릭터와 현재 장면만 준비한 뒤 카운트인을 시작합니다. `loadProfiles.assetIds`가 장면별 목록입니다.
3. 장면을 떠날 때 사용하지 않는 텍스처를 해제합니다. 종이접기 전환 중 두 배경을 동시에 보유하면 표의 메모리보다 커집니다. 정지 전환 캡처나 저해상도 전환 레이어가 필요하면 별도로 검수하세요.
4. 교육 도식은 결과·도움 화면에서 한 장씩 읽고 닫을 때 해제합니다. 도식 10개를 모두 GPU 텍스처로 미리 올리지 않습니다.
5. `greenhouse_flower_0..3` 벡터와 `object.greenhouse.flower_*` 원화는 대체 관계입니다. 한 계열만 선택합니다. 벡터 모드로 바꿀 때 상태 매핑을 유지하세요.
6. SVG의 정확한 비례·음표·쉼표는 유지합니다. 이미지에서 음악 정답 시각을 역산하지 않습니다. UI 라벨과 조작은 실제 DOM으로 제공합니다.

## 크롭·앵커·고해상도 화면

- 배경의 4:3 크롭은 [64, 0, 1024, 768], 16:9 크롭은 [0, 60, 1152, 648]입니다.
- 원본 픽셀 좌표를 그대로 적용하지 마세요. 런타임 manifest의 축소된 `anchorPx`와 `cropRects`를 사용합니다. 정규화 앵커는 같습니다.
- 투명 여백을 트림하지 않아 원래 캔버스 기준을 유지합니다. 솜새 demo의 다른 발밑 Y 앵커도 개별 반영했습니다.
- 4:3 창의 유효 가로 1024px는 DPR 2에서 512 CSSpx, DPR 3에서 약 341 CSSpx까지 원래 해상도로 표시할 수 있습니다. 390 CSSpx/DPR 3에서는 약 1.14배 확대가 필요합니다. 넓은 태블릿과 높은 DPI의 품질이 중요하면 마스터 1536×1024를 별도 상위 해상도로 사용하세요. 모든 기기에 원본 픽셀 품질을 제공한다는 뜻은 아닙니다.
- 캐릭터는 투명 여백이 있어 512px 캔버스 전체가 보이는 그림 폭은 아닙니다. `visibleBoundsAlpha128`와 실제 CSS 크기를 함께 확인하세요.
- 배경은 움직임 축소 모드와 같은 파일을 공유합니다. 빈 놓기 원의 중심 뒤로 리본이 통과하지 않도록 분리합니다.

## 검증 범위와 남은 일

수행한 검사:
- 17개 이미지의 인코딩·디코딩과 원본 리샘플링 재계산
- 13개 투명 스프라이트의 RGBA/알파 완전 일치
- 배경 4개의 PSNR 34.37–37.18dB와 정지 시각 비교
- 75개 SVG의 원본 해시 일치, 모든 원본 92개 파일의 불변 확인
- 크기·크롭·앵커·장면별 파일 크기·디코드 메모리 수식의 독립 재검사
- 최종 ZIP 무결성 검사

미수행: 브라우저의 실제 WebP 디코드·폴백 동작, 실제 iPhone/Android의 성능·메모리·GPU 측정, 런타임 포즈 전환, 오디오 청음, 교육자 기보 최종 승인. 교육 도식의 출시 승인 상태는 false/pending을 유지합니다. 이 파일들은 애니메이션 리그나 완성된 게임이 아닙니다.

정지 비교 보드는 Pillow로 WebP를 실제 디코드한 픽셀을 사용합니다. 설치된 Inkscape의 WebP 가져오기는 지원되지 않아, 문서 렌더링에만 디코드 결과를 PNG로 전달했습니다. 런타임 WebP 파일은 변경하지 않았습니다.

## 재생성

원본 `dream/`과 이 `dream_runtime/`을 같은 부모 폴더에 두고 Python 3 + Pillow 12.3.0(WebP 지원) 환경에서 실행합니다.

    python source/build_runtime.py

정지 비교 보드는 Inkscape 1.4로 생성합니다.

    python source/build_comparison.py

마스터 PNG는 읽기만 하며 변경하지 않습니다. 최종 WebP 해시는 런타임 manifest로 고정합니다. 원본 팩의 권리·라이선스·검수 조건도 동일하게 적용됩니다. 인코딩 파생본에는 원본의 모든 메타데이터가 그대로 유지되지 않을 수 있으므로 원본 팩과 해시 매핑을 함께 보관하세요.
